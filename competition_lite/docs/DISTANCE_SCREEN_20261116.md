# 大幅查询优化：紧凑筛选与双精度复核

以已推送 **05212db** 为基线，最终单轮无过滤平均请求 **0.337945→0.179822 ms，1.88 倍**；两组混合平均请求 **0.242674→0.161932 ms，1.50 倍**；含驱动生成请求的整个查询区间 **0.291981→0.209050 s，1.40 倍**。查询区间容器 CPU 0.158699→0.077302 s，减少 51.29%。这些是不同指标，**没有达到混合端到端 2 倍**。保留这个有明显收益且保持 Exact 结果的版本。

## 为什么有效

第一种 float 筛选实验虽然将无过滤 double 复核数从 10000 降到约 195，仍要读取 5.12 MB 原矩阵；距离阶段没有明显改善，关闭筛选甚至更快，因此放弃。仅增加算术模块并不能解决这项成本。

最终方案在原矩阵旁构建有界 int8 筛选数据。过滤候选读取按行编码；无过滤读取每组 16 条向量的交错编码，通过 AVX-512 VNNI 同时计算 16 个整数距离，使用四条独立累加链。每次无过滤扫描的主要编码数据为 1.28 MB，只有可能进入 Top-K 的向量才回读原 float32 数据、用原来的 double 内核复核。所有返回距离和最终排序仍使用复核值，不用量化距离排名或输出。

默认输入上平均 double 完整距离数由无过滤 **10000→315.66**、过滤 **500→221.672**；这不代表没有计算其他向量：仍完整读取每个候选的 128 个编码坐标。统计的总处理维数包含编码筛选与 double 复核，分别为 1320404.48/92374.016，高于原 1280000/64000；收益来自更少的原向量访问和更便宜的算术。

`LITE_DISTANCE_SCREEN=0` 关闭新缓存构建与筛选，恢复原路径；`LITE_SCREEN_DOT=0` 关闭交错编码与 VNNI，只使用按行整数编码作对照。仅在热表 128D、矩阵有预算、CPU 支持 AVX-512BW 和默认浮点环境时建立编码；VNNI 再单独检查 CPU 支持。其他维度、无矩阵、冷表、AVX2/scalar 等继续原执行器。非默认舍入、FTZ、DAZ 环境不执行筛选。Block 和部分距离提前终止不叠加这条路径。

编码沿用矩阵的槽位及失效规则，更新、删除、失败语句、事务回滚、表/列切换、GC、清缓存都会使其失效。它不缓存查询答案，也不写入 WAL/SST/Manifest。每矩阵按行编码上限 2 MiB；交错编码及范数另有同级上限，原矩阵加编码仍受原 `LITE_MATRIX_MB` 预算检查。默认数据额外持有 **2600000 bytes**：行编码 1280000、交错编码 1280000、整数范数 40000。

## 正确性与验收

筛选规则的推导、整数范围和浮点保护见 [误差界说明](DISTANCE_SCREEN_BOUND.md)。不能只凭随机测试证明下界；测试用于核对实现是否符合该设计。

- 921088 个阈值判定，对照原 double 内核和独立 long double，196881 次拒绝均安全。覆盖随机浮点位模式、宽指数范围、次正规数、最大值、相等/相邻 float、查询超出编码范围、阈值上下相邻 double；5281 个查询坐标发生裁剪。VNNI/按行整数距离逐项相同，检查非对齐输入、16 行起点和尾部掩码。
- 384 条专门的 Exact 查询：随机数据、近距离并列、极小值、float 算术会溢出的值，K=1/10/257/2500，多种过滤、更新/删除、事务内视图、回滚和重启。全部与关闭筛选的原精度路径及独立真值核对。
- 实际 Docker 完整 gate 通过：公开 20、补充 12、边界、1470 Exact、864 原内核路径、数值/JSON、LSM 模型/损坏、提交故障、42 个 LSM 故障、72 个向量 WAL 故障，以及上述两项新专项。
- AVX2、无矩阵、冷表、仅行编码各 384 条回退对照通过。新内核与全部 384 条新查询路径的 ASan/UBSan 通过。
- 最终三版共 3000 条主查询通过独立数量、去重、过滤、Top-10 ID/顺序及重算距离检查；两组 Recall@10 均 1.000。重启累计逐行核验 30000 行。未使用官方提测次数。

保留失败实验：dev1 初始“极小值+坐标置换”专项在独立 fsum 的并列顺序检查失败，但新旧路径结果相同，暴露的是既有 double 与 fsum 的舍入顺序差异。随后改用重复坐标构造可无歧义验真的极值集合，并扩大指数范围；失败日志和后续结果都保留。dev1 float 筛选因无性能收益退出，dev2/3/4 分别验证 int8、交错 VNNI 和多累加链，不隐去中间结果。

## 版本身份与复现

最终源码 CPP SHA256 `f56625874509a27b8b4aa7aae0975d8e70077ee006b424f0dcaf708faaeac771`；LSM 头文件未改，SHA256 `76b41f66e7dd78ab7713944c8d650b3eaf31209759a3d0c4d182cbb1e0622bf9`。实际 Docker 与计时二进制 SHA256 均为 `e12a42d16fc2846d5eb612b27dddf2c73fddeb6729ab3d191022991e34387bc2`，运行时 **1995 行**。

输入 insert SHA256 `cbed135375c7deea4b8342e0b0e2deed667e5694c9212054e0bf9b0c1fd0771d`，cases SHA256 `c8ecc80cf5baca8a83204a54ad07cf8737c46e56b1175e216aea0f8469afc504`。必要原始结果见 [evidence.json](../results/distance_screen_20261116/evidence.json)；服务器完整记录位于 `/mnt/SSD1/zzp/seekdb-round2-lite2000/distance-screen-20261116/dev1` 至 `dev4`，没有额外服务器打包归档。复现脚本见同一 results 目录的 orchestration。

本轮交付的是无过滤接近两倍、混合请求约 1.50 倍的查询改进。更高整体收益仍需处理过滤查询的固定开销，并受运行环境/CPU 支持影响；不能保证官方隐藏门槛或分数。
