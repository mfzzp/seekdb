# 128D 整数筛选的安全边界

本路径只作拒绝判定。最终距离和 Top-K 比较始终调用既有 double 内核。下述假设对应实际构建：有限 float32 输入、IEEE binary64、默认 round-to-nearest、无 FTZ/DAZ、未启用 fast-math。运行时检查 MXCSR 舍入/FTZ/DAZ 位；不满足时回退。所有向量和查询先经过原有有限值与维数校验。

## 精确算术下的判定

令 `s = max(abs(所有矩阵坐标))/127` 为程序实际存储的正 double 标量，全零矩阵不建立编码。数据编码为 `z_j = round(x_j/s)`，范围 [-127,127]。查询编码 `w_j` 是 `q_j/s` 四舍五入并裁剪到同一区间。定义：

```
E_x >= ||x/s - z||₂
E_q >= ||q/s - w||₂
I   = Σ (z_j - w_j)²
```

三角不等式给出 `sqrt(I) <= ||x-q||₂/s + E_x + E_q`。因此，如果已知第 K 名距离平方阈值 T，只有在 `I > (sqrt(T)/s + E_x + E_q)²` 时才能安全拒绝。严格大于保留边界和主键并列候选；不足 K 条时阈值为无穷，不拒绝任何候选。批量过程中使用稍旧的堆阈值只会减少剪枝，不会增加错误拒绝。

## 对实现误差的保护

binary64 的单位舍入误差 `u=2^-53`。矩阵比例 `s` 是一个确定的 double 值，推导以它为准，不要求它等于无限精度 max/127。数据的 `x/s` 绝对值约不超过 127，除法引入的绝对误差小于 2e-14；最近整数编码误差因此不超过 `0.5+2e-14`。代码采用更宽的 `sqrt(128)*(0.5+1e-9)` 作为统一数据误差界。

查询可以超出数据范围，不能假定其裁剪误差也只有 0.5。代码逐坐标计算裁剪后的残差平方和，再取平方根，使用 `computed_norm*(1+1e-12)+1e-9` 作为查询误差保护。128 个非负项的 double 求和、平方、除法和开方的相对误差在约 1e-14 量级；残差相减的绝对项由 1e-9 余量覆盖。与编码整数相近时，除法误差仍远小于该余量；远离编码范围时，残差随查询值增长，相对余量生效。

原 double 距离内核本身也可能略低于无限精度 L2 平方和，因此比较阈值里的 `sqrt(T)` 额外乘 `1+1e-12`，大于 128D 原内核的舍入误差界。计算半径后的平方再乘 `1+1e-12`，覆盖阈值除法、相加和平方的舍入。

浮点范围没有隐藏的下溢漏洞：非零 float32 的最小值约 1e-45，`s` 至少约 1e-47；最大的归一化坐标量级约 1e85，128 项残差平方和小于 1e174，远低于 double 上限。最小非零 float32 差值的平方约 1e-90，远高于 double 正常数下限。全零时不建编码；初始无限阈值保持无限。保护项使边界更宽，只增加复核。

## 整数内核与最终精度

每坐标整数差在 [-254,254]，128 项平方和最大为 **8258048**，可由 int32 精确表示。按行内核先扩宽到 int16 再做乘加；VNNI 使用 unsigned `(z+128)` 与 signed `w` 点积，通过 `norm(z)+norm(w)+256*sum(w)-2*dot(z+128,w)` 恢复相同整数平方距离，所有中间值也远小于 int32 上限，使用非饱和乘加。

VNNI 与按行结果逐整数对比，误差测试另外用 long double 和原 double 距离验证拒绝条件。通过筛选的候选不改变原向量，不改变原 double reduction 顺序；真实主键决定距离相同的顺序。紧凑编码与数据更新一起失效，不能拿旧距离参与新记录的排序。

测试不是这项推导的替代品。后续若改编码位数、维数、累加方式、误差常数、舍入环境或编译浮点选项，必须重新审计此边界；不能只看到普通随机数据 Recall=1 就启用新剪枝。
