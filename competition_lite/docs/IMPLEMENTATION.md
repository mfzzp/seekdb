# 当前实现：以 SST 为主存储的单写者 LSM

根 Dockerfile 编译 `src/minivectordb_lite.cpp` 与其包含的 `src/lsm_store.hpp`。两者都计入运行时代码行数。正常执行不再使用全量 STATE 快照、内存行表主存储或 SQL token WAL；旧的未使用 PQ 训练代码已移除。

## 数据组织

| 数据 | 当前组织 |
|---|---|
| Schema、行数、索引声明、插入序号 | LSM catalog 键，与行修改原子提交 |
| 主行 | 表名前缀 + 有序有符号 64 位主键；字段、向量偏移均有长度编码 |
| 普通列索引 | 表 + 列 + 类型规范化值 + 主键；与主行同时维护 |
| 向量 | 独立追加 float32 文件；默认 32 MiB mmap 窗口 |
| 内存写入 | 有序 MemTable，默认 4 MiB；事务和语句各有可溢写的私有写集 |
| SST | 约 32 KiB 数据块、CRC32C、稀疏块索引、校验过的文件尾；目标 8 MiB |
| 热表缓存 | 最多一张表，保守估算上限 32 MiB；矩阵另限 64 MiB |

普通读取合并 MemTable 与相关 SST，按记录版本取最新值；事务叠加私有写集，删除标记遮蔽旧行。同一事务反复更新、删除后重新插入都有最后写入语义。

小表延迟构建可失效的热表缓存，使用 postings、连续矩阵、SIMD 与 Top-K。准备时间计入首次请求或单列预热。超出容量或 `LITE_ROW_CACHE_MB=0` 时直接流式读 SST：主键等值点查、主键有序范围、普通列等值二级键查找，所有剩余谓词仍验证。没有查询结果缓存。

`LITE_EXACT_PATH=auto|scan|block` 保留，auto 选择 scan。热表支持显式 Block 对照；冷表使用精确扫描。过滤、float32→double 距离和并列 id 排序保持一致。ANN 明确回退 exact，不声称近似搜索已通过召回验收。

## 写入与事务

BEGIN 只建立写集和向量边界，不复制表。语句先写私有批次，成功后并入事务；失败丢弃该语句和新增向量，保留之前的事务修改。写集按容量溢写，按大小分组归并，避免长事务反复重写整个写集。ROLLBACK 丢弃写集，无需恢复整表副本。

非空提交顺序：向量写完整并 fdatasync → 写含版本区间、记录数和向量边界的 WAL BEGIN / records / COMMIT 并 fdatasync → 应用 MemTable、必要时刷 SST → 成功响应。WAL 存实际键值修改，不再保存待重放 SQL。每次提交仍保留两次同步。

短写和 EINTR 重试。I/O 或校验失败冻结引擎，避免截断可能已经提交的向量。目录文件锁禁止两个写进程同时打开。

## 刷盘、合并和回收

刷盘移交 MemTable；多路合并只保留每个有序层当前文件的一个数据块。L0 达四个文件触发归并，后续层按 8 倍容量增长，可以继续向更深层推进。高层选择一个源文件及下一层重叠文件，按目标大小输出。分层合并保留墓碑，全量覆盖全部版本时才删除墓碑。

Manifest 校验文件清单、键范围、层级、大小、最高序号、持久化序号、向量代际/边界和 WAL 代际。新文件同步 → Manifest 同步、原子发布、目录同步 → 标记旧文件回收；读视图引用释放后才删除旧 SST。发布失败保留恢复可能依赖的旧文件。当前合并是同步的，没有后台线程。

## 恢复与维护

启动加载 catalog 和文件元数据，从 Manifest 指向的 SST 与 WAL 恢复。先验证完整 WAL 事务，再重放高于持久化序号的记录。大事务部分刷盘、恢复中再次崩溃均按记录序号继续。不完整未提交尾部截断；完整帧校验错误拒绝加载。

Checkpoint 刷出记录，创建并同步新 WAL，原子发布引用新 WAL 的 Manifest，之后回收旧 WAL；不写全表 STATE。GC 固定 checkpoint，流式复制活向量并生成新偏移的 SST，新向量和 SST 由同一个 Manifest 原子切换后回收旧代际。

旧 Lite STATE v3 / typed-token WAL 导入独立代际，全部完成后才发布新 Manifest。v2/JSON 仅在旧 WAL 为空时支持，因为它没有可靠重放边界。历史 SST 的最后字段编码缺陷不用于迁移真值。导入后不再依赖旧 STATE/WAL；旧格式文件保留供核查。新格式孤儿文件启动时回收。

`--check` 遍历所有引用 SST，校验数据块、索引、键序和版本范围；`--maintenance flush|compact|gc` 执行维护并完成 checkpoint。

## 边界

这是现有 JSONL/SQL 契约下可磁盘主读、恢复、流式合并的单写者 LSM，没有多客户端 MVCC、后台 compaction 或通用 SQL 优化器。文件元数据随文件数增长；请求解析和响应也占内存，冷表结果物化上限 64 MiB，超限明确报错要求 LIMIT，不静默丢行。
