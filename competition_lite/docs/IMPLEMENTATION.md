# 当前代码实现思路

这是面向比赛 JSONL 协议的独立 C++17 单写者引擎。重点是内存查询、连续向量访问和可恢复的同步提交；它尚不是完整的通用 LSM 数据库。根 Dockerfile 编译 `competition_lite/src/minivectordb_lite.cpp`。

## 数据放在哪里

| 内容 | 组织方式 | 作用 |
|---|---|---|
| 普通字段、行信息 | 内存行表，主键定位 | 可见性、投影、修改与过滤 |
| 普通列索引 | 等值 postings、数值有序索引 | 缩小查询候选 |
| 向量 | 独立追加 float32 文件，行内保存偏移 | 减少文本和对象开销 |
| 向量访问 | 256 MiB mmap 窗口；小表可建立有上限的连续矩阵缓存 | 供 SIMD 距离内核使用 |
| WAL | 事务开始、typed token 修改记录、提交帧；CRC32C 与 8 字节对齐 | 恢复 checkpoint 后完整事务 |
| checkpoint | STATE、postings、向量块统计和向量索引文件 | 缩短恢复与索引准备时间 |
| MemTable / SST / Manifest | 修改记录、排序刷盘、分层合并与文件清单 | 已实现存储维护，尚未接管主读取路径 |

没有查询结果缓存。每条 SELECT 都从当前可见行重新计算。

## exact 怎么执行

普通列索引候选 → 完整 WHERE 过滤 → 按物理位置组织候选 → 向量读取与 SIMD L2 → 有界 Top-K → 按距离及 id 排序、输出结果。

- **直接扫描**是默认路径。SELECT 不构建 Block、不计算或排序下界。
- **Block 路径**使用同一批候选、同一个距离内核和 Top-K，只增加块下界与安全排除。只计算包含候选的块的下界。
- `LITE_EXACT_PATH=scan|block|auto` 控制选择；目前 auto 明确等同 scan，不是自适应优化器。
- `LITE_PROFILE=1` 提供候选数、完整距离数、剪枝数及阶段耗时；正式计时默认关闭。
- 随机高维数据上，本地对照未见 Block 剪枝收益，因此默认 scan。有物理聚类的数据仍可对照 Block。

## 写入、事务和恢复

SQL 解析后先验证、更新内存行和普通列索引；向量进入追加缓冲，修改记录进入待提交列表。成功提交顺序为：

**向量完整写入 → 向量文件 fdatasync → 完整 WAL 事务写入 → WAL fdatasync → 更新 MemTable／必要的刷盘 → 返回成功。**

每次成功的非空提交仍有向量和 WAL 两次同步，没有通过扩大批次、减少提交次数或取消持久化加速。

- WAL 描述符复用，事务帧先连续编码再完整写入；短写与 EINTR 会重试。
- CRC32C 支持 SSE4.2，缺少指令时使用查表实现；多项式和磁盘字节格式保持一致。
- MemTable 和 WAL 维护累计字节数，不再每次提交重扫全部内存记录或查询 WAL 文件大小；恢复打开文件时读取已有长度，checkpoint 后重置。
- `BEGIN` 仍复制整份表状态，支持整个事务的回滚。INSERT 单条语句失败用新增行及向量边界撤销，避免再次复制整张表。UPDATE / DELETE 的语句快照仍保留。
- 遇到提交写入或同步错误，停止接受后续操作及 checkpoint，要求重启。不能在 WAL 可能已提交时回滚并截断其向量。
- 恢复使用 STATE 的向量边界和 WAL 完整事务；未提交向量尾部截断，完整帧 CRC 错误拒绝加载。

## 文件发布

SST 与 sidecar 写完、同步后，写入并同步新的 Manifest，原子发布，切换当前视图，同步目录，最后回收旧文件。失败时保留仍可能被恢复使用的旧文件。当前没有并发 SST 读者。

## ANN 与未完成项

ANN 已实现 IVF 分桶、PQ 近似评分和原始向量精排，但此前服务器无过滤召回只有约 3.60%，尚未修复或宣称达标。

接下来仍需按实际提测反馈决定优先级：完整增量事务写集、SST 主读／主恢复路径、更多持久化发布故障检查、ANN 召回，以及大数据量下 mmap 访问成本。当前 Windows 本地验证不替代 Linux/Docker 提测，也不代表正式得分。
