# 当前实现：以 SST 为主存储的单写者 LSM

根 Dockerfile 编译 `src/minivectordb_lite.cpp` 与其包含的 `src/lsm_store.hpp`。两者都计入运行时代码行数。正常执行不再使用全量 STATE 快照、内存行表主存储或 SQL token WAL；旧的未使用 PQ 训练代码已移除。

## 数据组织

| 数据 | 当前组织 |
|---|---|
| Schema、行数、索引声明、插入序号 | LSM catalog 键，与行修改原子提交 |
| 主行 | 表名前缀 + 有序有符号 64 位主键；字段、向量偏移均有长度编码 |
| 普通列索引 | 表 + 列 + 类型规范化值 + 主键；与主行同时维护 |
| 向量 | 独立追加 float32 文件；默认 32 MiB mmap 窗口，最多保留 1 GiB 虚拟映射；驻留页计入容器内存 |
| 内存写入 | 有序 MemTable，默认 4 MiB；事务和语句各有可溢写的私有写集 |
| SST | 约 32 KiB 数据块、CRC32C、稀疏块索引、校验过的文件尾；目标 8 MiB |
| 热表缓存 | 最多一张表，保守估算上限 32 MiB；矩阵另限 64 MiB |
| SST 读取缓存 | Reader、索引、已解码块合计默认 16 MiB 保留预算；最多保留 64 个 Reader，活动游标工作集另计 |
| 紧凑查询视图 | 跨表默认 8 MiB；16 字节主键/向量偏移描述符，以及同预算内的二级候选位置 |

普通读取合并 MemTable 与相关 SST，按记录版本取最新值；事务叠加私有写集，删除标记遮蔽旧行。同一事务反复更新、删除后重新插入都有最后写入语义。

小表延迟构建可失效的热表缓存，使用 postings、连续矩阵、SIMD 与 Top-K。准备时间计入首次请求或单列预热。超出容量或 `LITE_ROW_CACHE_MB=0` 时，Exact 可使用有界的紧凑查询视图：只持有主键与当前向量偏移，普通列等值索引在同一预算内转换为描述符位置。原始向量仍读现有文件，输出字段只对最终 Top-K 取完整行。无法由元数据判定的剩余谓词会使查询回退，不能先选 K 条再补过滤。更新、失败语句、回滚及 GC 均失效或重建视图。没有查询结果缓存。

紧凑视图装不下或 `LITE_QUERY_VIEW_MB=0` 时，主键点查、范围扫描和普通列过滤继续走真正的 SST 路径。二级候选每批最多 1024 个主键，排序去重后各 SST 只建立一个持续定位的游标，与 MemTable、事务私有层按原版本规则归并。候选在某个 SST 中密集且覆盖大部分块时，自动改为持续推进。`LITE_LSM_READ=batch|scan` 可强制批量或主行扫描过滤，并绕过紧凑视图；默认 auto。范围 MemTable 游标只快照所需键区间，不再为小范围复制全部 MemTable。

不可变 SST 的 TableReader 与游标位置分离：按唯一文件身份复用句柄和已校验索引，块缓存保存已验证、已解码的记录。缓存未命中仍验证 CRC，`--check` 强制绕过缓存核验磁盘。回收清除缓存引用，正在读取的游标仍保护旧文件。`LITE_READ_CACHE_MB=0` 关闭保留；活动游标、临时解码缓冲与诊断集合不能冒充已包含在保留预算中，实际内存以容器峰值为准。

向量 mmap 窗口保留减少交替访问及顺序扫描中的反复映射，不复制完整向量矩阵。`LITE_MMAP_KEEP_MB=0` 恢复单窗口；至少保留一个工作窗口。向量截断和文件代际切换前清除所有映射，跨窗、文件增长、回滚和 GC 有专项检查。

`LITE_EXACT_PATH=auto|scan|block` 保留，auto 选择 scan。热表支持显式 Block 对照；冷表使用精确扫描。过滤、float32→double 距离和并列 id 排序保持一致。ANN 明确回退 exact，不声称近似搜索已通过召回验收。

热表无过滤路径按矩阵批次扫描，128 维 AVX-512 复用已扩展为 double 的查询向量；有过滤候选默认两向量交错计算。距离超过当前 Top-K 阈值的行不读取主键，距离相等时仍读取真实主键比较；输出和可见性不变。各 ISA 保留原双精度归约次序。提前终止只作显式实验，默认关闭；`LITE_MATRIX_MB=0` 真正禁用矩阵。标量、AVX2、单/双/四向量、矩阵批次及查询复用均可独立选择做消融，完整接口见 README。

过滤后的物理位置若组成连续区间，也复用矩阵批次扫描，从区间真实起点开始，不扫描未匹配记录。`LITE_CONTIGUOUS_SCAN=0` 关闭对照。8000 候选范围组五轮约改善 4.9%；默认混合查询基本持平。准备阶段仍有成本，未声称全部过滤已优化到位。

## 写入与事务

BEGIN 只建立写集和向量边界，不复制表。语句先写私有批次，成功后并入事务；失败丢弃该语句和新增向量，保留之前的事务修改。写集按容量溢写，按大小分组归并，避免长事务反复重写整个写集。ROLLBACK 丢弃写集，无需恢复整表副本。

默认非空提交顺序：向量写完整 → 写含版本区间、记录数、向量代际/区间、原始 float32 字节和键值修改的完整 WAL 事务 → WAL fdatasync → 应用 MemTable、必要时刷 SST → 成功响应。大事务的向量按有界块记录，完整 COMMIT 前不发布记录。`LITE_COMMIT_MODE=dual` 保留先同步向量再同步旧格式键值 WAL 的对照。

普通提交只要求 WAL 同步；**自动 MemTable flush、手工维护及 checkpoint 发布 Manifest 前仍必须同步其引用的向量边界**，不能只保护显式 checkpoint。持久边界跟踪避免重复同步。同步成功后的 WAL 完整页以 best-effort `POSIX_FADV_DONTNEED` 提示释放，失败不改变恢复语义；`LITE_WAL_CACHE=1` 保留缓存作对照。可选 `LITE_WAL_BATCH=1` 合并有界 WAL 帧输出，默认关闭。

短写和 EINTR 重试。I/O 或校验失败冻结引擎，避免截断可能已经提交的向量。目录文件锁禁止两个写进程同时打开。

## 刷盘、合并和回收

刷盘移交 MemTable；多路合并的每个有序层游标只持有当前文件的一个数据块，共享读取缓存另受保留预算限制。L0 达四个文件触发归并，后续层按 8 倍容量增长，可以继续向更深层推进。高层选择一个源文件及下一层重叠文件，按目标大小输出。分层合并保留墓碑，全量覆盖全部版本时才删除墓碑。

Manifest 校验文件清单、键范围、层级、大小、最高序号、持久化序号、向量代际/边界和 WAL 代际。新文件同步 → Manifest 同步、原子发布、目录同步 → 标记旧文件回收；读视图引用释放后才删除旧 SST。发布失败保留恢复可能依赖的旧文件。当前合并是同步的，没有后台线程。

## 恢复与维护

启动先加载 Manifest 元数据并打开向量代际，再验证完整 WAL 事务及向量区间覆盖。恢复使用不带 O_APPEND 的独立描述符按绝对偏移重写向量，覆盖“长度不变但数据丢失”的情形，然后重放高于持久化序号的键值；向量不能仅因对应键值已进入 SST 而跳过。大事务部分刷盘、恢复中再次崩溃均幂等继续。不完整未提交尾部截断；完整帧校验、区间或代际错误拒绝加载。

新发布 Manifest 为 v4，读取 v3 后先按旧 WAL 语义恢复并 checkpoint 再服务。旧版本程序拒绝 v4，避免把新的提交契约误当成双同步。已发布向量前缀损坏而又无完整恢复来源时继续报错，不补造数据。

Checkpoint 刷出记录，创建并同步新 WAL，原子发布引用新 WAL 的 Manifest，之后回收旧 WAL；不写全表 STATE。GC 固定 checkpoint，流式复制活向量并生成新偏移的 SST，新向量和 SST 由同一个 Manifest 原子切换后回收旧代际。

旧 Lite STATE v3 / typed-token WAL 导入独立代际，全部完成后才发布新 Manifest。v2/JSON 仅在旧 WAL 为空时支持，因为它没有可靠重放边界。历史 SST 的最后字段编码缺陷不用于迁移真值。导入后不再依赖旧 STATE/WAL；旧格式文件保留供核查。新格式孤儿文件启动时回收。

`--check` 遍历所有引用 SST，校验数据块、索引、键序和版本范围；`--maintenance flush|compact|gc` 执行维护并完成 checkpoint。

## 边界

这是现有 JSONL/SQL 契约下可磁盘主读、恢复、流式合并的单写者 LSM，没有多客户端 MVCC、后台 compaction 或通用 SQL 优化器。文件元数据随文件数增长；请求解析和响应也占内存，冷表结果物化上限 64 MiB，超限明确报错要求 LIMIT，不静默丢行。

LSM 主读取与恢复的初始验证见 [LSM 报告](LSM_20261115.md)；后续读取修复见 [读取路径报告](READPATH_20261115.md)。公开及本地回归通过不等于正式 29 项或官方分数保证。
