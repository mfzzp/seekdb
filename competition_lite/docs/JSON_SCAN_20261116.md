# 综合指标第二轮：JSON 输入字符串扫描

在已推送 10bc575 的 mmap 内存优化上，只优化 jstr 的普通字节扫描。SSE2 每组检查 16 bytes 的引号、反斜杠和控制字符，连续片段一次追加；特殊字符和 Unicode/surrogate 保留原解析逻辑。无符号比较保证 >=128 的原始字节保持既有行为；只在至少剩余 16 bytes 时加载。`LITE_JSON_SCAN=0` 保留逐字节对照。没有修改 SQL、距离、事务或持久化格式。

## 验收与身份

47724 组输入与独立保留的旧解析器对照输出字节、错误码、错误消息及停止位置。覆盖全部 256 字节的不同偏移、随机输入、JSON 往返、控制字符、转义、surrogate、非零起点、未闭合和各种短尾；ASan/UBSan 同样全部通过。普通无转义字符串的微测有 7.9–23.9 倍改善，不能当作数据库倍数。

实际 Docker 完整 gate 通过，包含公开 20、补充 12、协议边界、1470 Exact、864 内核路径、矩阵映射、筛选数值/路径、LSM 模型/损坏及提交/恢复故障。三版三轮 9000 条主查询和 90000 行重启核验均通过，两组 Recall@10=1.000，数量、去重、过滤、ID/顺序和距离逐项核对。没有使用官方提测次数；本地公开通过不保证隐藏用例。
