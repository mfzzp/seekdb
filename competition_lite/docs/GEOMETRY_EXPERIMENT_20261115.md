# 几何有序 Block：隔离实验与保留标准

这是一项第三轮实验，尚不属于提交运行时的能力。`bench/geo_experiment.py` 从明确的基础源码生成隔离副本，保留基础与生成源码的 SHA256；生产 Dockerfile 只编译 `src/`，不会执行该生成器。默认正式执行器仍采用 scan。实验使用 `LITE_EXACT_PATH=geo`，并同时保留同二进制 scan/物理 block 与冻结 `9884dd3` 对照。

## 布局和生命周期

复用热视图的物理位置、真实主键和已有版本可见性。选择首个可见向量为参考点，保存向外扩张的半径区间，按 `(半径下端, 主键)` 排序位置。每 64 个位置组成一个块，记录区间并集；order/rank 定位物理向量，块起止位置给出有效候选数。没有复制全量向量矩阵，没有另建 RowID 或版本系统。半径下端是确定性的保守排序代理，块界覆盖其全部成员，不要求真实半径排序完全一致。

每表只缓存一个向量列；列切换重建。热表重建、索引重建、冷却、目录重载（含回滚、恢复、GC）与现有矩阵/物理块缓存同时失效。构建临时与持久元信息按每行 48 字节估算，默认超过 16 MiB 回退扫描；仍受现有热视图/冷 SST 路径限制。`LITE_GEO_MB` 控制实验额度。过滤后少于 2048 个候选在构建几何缓存前回退，`LITE_GEO_MIN=1` 仅用于覆盖小候选测试。

几何访问重新排列位置，不假定向量在矩阵内连续。无过滤复制缓存顺序；大候选以字节标记交集后顺序收集，小候选按 rank 排序。这些准备和块访问排序都计入查询成本。

## 浮点下界

输入是有限 float32，距离采用 double，不启用 fast-math。每个减法、平方、非负求和和平方根都通过 `nextafter` 向两侧包围，得到包含真实实数欧氏距离的 `[lo,hi]`。float32 非零差值的平方远大于 double 最小正规数；有限 float32 在支持维度下的平方和远低于 double 最大值。零值和中间下溢仍用外扩区间覆盖。

对查询参考距离区间 Q 和块半径区间 B，令 `delta=max(B.lo-Q.hi,Q.lo-B.hi,0)`，减法向下舍入，再将平方向下舍入，得到真实平方距离的下界。Top-K 存的是经舍入的 double 平方和，故还将界乘以 `1-min(1,8*(d+1)*epsilon_double)` 并向下舍入。每维减法/平方与最多 d 次非负求和的标准相对误差界小于该折扣；各 SIMD 分组的路径更短。折扣达到 1 则界为零。仅当界**严格大于**当前完整 Top-K 阈值时跳过，不能用大于等于处理并列。

`geo_bound_check.cpp` 独立 long double 核对半径包围，并将界与 scalar/AVX2/AVX-512 完整距离及相邻阈值比较，包含极小/极大 float、相同向量和邻近值。数值抽查是回归验证，不替代上述区间与舍入论证。

## 实验与验收

同输入三轮、轮换顺序。原始 10000×128 默认负载，以及固定种子 32 簇、打乱物理装载顺序的 10000×128 和 10000×3；聚簇组含无过滤、500 等值候选和 8000 范围候选。真值计算独立于引擎，全部结果和重启全量行/向量均核对。

正式计时与诊断分开。首次构建记录在 warmup 原始记录中，且包括在五段完整流程；不能只报告缓存建立后的查询均值。报告完整计算数、构建/下界/排序与访问阶段、容器峰值和实际可用的资源计数。既有 Exact 模型复用到 geometry，并补强制小候选、向量列切换、更新、删除、回滚、GC 和重启；奇数维度及 mmap 跨窗在各 ISA 下对照，另跑 ASan/UBSan。

是否进入正式实现取决于含准备成本的净收益。随机高维无效时不启用默认；若仅聚簇负载有效，保留为可复现实验，不把该收益宣传为官方负载的提升。

## 三轮结果与结论

测试已完成。正式 scan 运行时 `5d91391` 不再更改；以下 scan/block/geo 为同一隔离二进制，另有冻结 `9884dd3` 检查编译布局影响。每组内部使用相同输入和 2 CPU/2 GiB/no swap 配置，计时和阶段诊断中的引擎通过 sched_setaffinity 固定 CPU 0/1。Docker 的 cpuset 控制器不可用警告保留原文；这里不声称依赖 Docker cpuset 完成绑定。各组以下均为三轮中位数。

| 数据/查询数 | Scan 平均 ms | 物理 Block 平均 ms | 几何 Block 平均 ms | Scan 完整流程 s | 几何完整流程 s |
|---|---:|---:|---:|---:|---:|
| 默认随机 128D / 1000 | 0.281738 | 0.383298 | 0.480104 | 1.025335 | 1.311685 |
| 打乱物理顺序、32 簇 128D / 300 | 0.568673 | 0.620290 | 0.470503 | 0.884823 | 0.903156 |
| 打乱物理顺序、32 簇 3D / 300 | 0.401279 | 0.461617 | 0.415466 | 0.611892 | 0.635177 |

冻结 9884dd3 的平均请求分别为 0.279174、0.566704、0.405765 ms，接近同二进制 scan。随机组 scan/block/geo 容器峰值分别 24,981,504/24,772,608/24,248,320 B，聚簇 128D 为 24,805,376/25,292,800/25,174,016 B，3D 为 13,959,168/14,405,632/14,479,360 B；波动值不作为几何布局节省内存的证据。设备 I/O 同样不可用，完整原始资源记录保留。

单独诊断给出原因：

| 数据 | 无过滤完整计算 Scan→Geo | 8000 候选计算 Scan→Geo | Geo 首次构建 ms |
|---|---:|---:|---:|
| 随机 128D | 10000→10000 | 本组没有范围过滤 | 55.664 |
| 聚簇 128D | 10000→573.28 | 8000→458.76 | 47.437 |
| 聚簇 3D | 10000→250.24 | 8000→214.98 | 2.572 |

随机组没有剪枝，几何顺序使无过滤访问/距离从约 0.189296 增至 0.387239 ms，另付下界约 0.017152 ms、排序约 0.005157 ms。正式混合平均慢约 70%，含构建的完整流程慢约 28%，明确不进入默认路径。

聚簇 128D 的无过滤访问/距离从 0.183605 降到 0.028946 ms；但每次仍有约 0.055900 ms 准备、0.014981 ms 下界和 0.004247 ms 排序。8000 候选准备约 0.667271 ms、几何排序约 0.036743 ms，访问/距离已降到 0.025330 ms。平均查询改善约 17.3%，但 300 次查询不足以抵消首次构建，本轮完整流程仍慢约 2.1%。这不代表更多重复查询的聚簇负载永远无收益；当前证据只支持这次查询数和输入，不外推未测试的摊销点。

3D 虽减少了约 97.5% 的无过滤完整距离，距离原本便宜，候选收集、下界和排序成为主要成本，完整流程仍慢约 3.8%。**少算向量不等于整体更快。** 500 候选各组均在构建前回退 scan，诊断 block_build/bounds/block_sort 全为零。

保留结论：保留生成器、证明、查询模型、数据生成器和原始实验；不合入生产 `src/`，不新增默认几何路径，不宣称官方负载提速。原始物理 Block 对照开关继续保留。

## 已通过的检查与一次驱动修正

7500 项半径包围/下界检查，1394 个正下界；默认候选门槛与强制小候选各 490 项 SQL 模型检查；auto/AVX2/scalar 各 864 项奇数维度、组尾和 mmap 跨窗检查；ASan/UBSan 几何 SQL 模型 490 项均通过。检查包含两向量列切换、更新、删除、回滚、GC、重启，全部三轮性能查询独立真值及重启全量核对通过。

3D 第一次在冻结原版基线的预热阶段失败：compare_run 用“维度是否等于 128”猜表结构，错误生成 tenant_id 等不存在列。已改为检查 prepared.columns；保留失败日志，在新结果目录重跑成功。128D 原始负载的预热生成保持相同。不是引擎正确性失败，更不能忽略失败后继续统计。compare_run 上传使用 CRLF、Git 存储 LF，两者哈希及仅行尾转换记录在 bench-source-verification.json；运行时源码哈希独立核对。
