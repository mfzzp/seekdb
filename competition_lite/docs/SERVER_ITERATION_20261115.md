# 服务器优化与六组指标：2026-11-15

本轮完成实际 Linux/Docker 验收，并减少 exact 的候选准备和无效索引训练。相对修复版 ce21bb9，1000 条查询的请求平均耗时下降 19.83%，容器峰值下降 12.41%；写入没有明确改善。相对曾取得约 2k 分的 f885c28，查询平均耗时下降 11.68%，但写入中位数高 4.16%、容器峰值高 12.66%。不能据此推算官方分数，也不能称为所有指标均领先的版本。

服务器 Xeon Gold 6430；实际 Docker Debian GCC 12.2.0，`-O3 -DNDEBUG -std=c++17 -Wall -Wextra`，2 CPU、2 GiB、swap=0；引擎绑定逻辑 CPU 0、1。主测试驱动和独立真值位于引擎容器外。各轮串行、轮换版本顺序，使用新数据库。容器保留一个 sleep 进程以读取 shutdown 后的峰值；这部分开销对各版本相同。

索引在写入之后创建，另计 index_s；18 次预热另计 warmup_s（最终版约 0.01394 s），包含首次连续矩阵准备。每条请求从发送预编码 JSONL 到读取并解析完整响应计时；数据生成、真值、校验和报告不在该区间。query_wall_s 还包含驱动生成查询 SQL、编码请求、保存结果的开销，因此与请求耗时之和分别列出。每轮 shutdown/checkpoint、重启也另计。未打开 LITE_PROFILE；阶段诊断单独运行。

## 实际代码改动

1. 选择候选时直接引用已有 postings，避免先复制整表 id 再复制候选；仅数值范围需要物化自己的列表。
2. 只跳过被选中索引确切保证的一个 WHERE 条件，其余条件逐条检查。BIGINT 查询字面量先规范化，修正 `n=+001` 未命中规范索引键的问题。
3. 无过滤扫描直接遍历连续行视图，省去位置数组；过滤后的物理位置已排序时不再重排。Block 仍是可选的独立路径。
4. ANN 已统一 exact fallback，当前请求和恢复不再训练、加载或维护未使用的 PQ 编码；索引声明仍进入 WAL/checkpoint，重复创建、回滚及重启语义保留。旧训练/持久化函数保留供独立研究，但没有挂在生产请求路径上。删除早已关闭的近似 SELECT 分支。

没有更改距离算术、结果并列排序、同步顺序或提交批量；没有查询结果缓存。

file_mapped 是文件页的子项，不能再次加总。容器当前内存、峰值、进程 RSS 不是同一指标。cgroup 的分项可能延迟更新，单次 BEGIN 前后的 anon 差值不应单独解释成复制内存。

当前 rootless Docker 仅委派 cpu/memory/pids，`io.stat` **不可用**；本轮无法提供 cgroup 存储层实际累计读写量，不能写成 0。作为辅助，以下是 `/proc/<engine>/io` 阶段差值的中位数，包含脏页记账口径，**不是官方 I/O 指标，也不是已完成落盘的精确字节数**：

| 阶段/计数，bytes | old | before | final |
|---|---:|---:|---:|
| 写入 read_bytes | 0 | 0 | 4096 |
| 写入 write_bytes | 5922816 | 6508544 | 6508544 |
| 写入 cancelled_write_bytes | 0 | 0 | 0 |
| 查询 read_bytes / write_bytes | 0 / 0 | 0 / 0 | 0 / 0 |
| 查询 rchar（含 JSONL 请求输入） | 1760080 | 1760080 | 1760080 |

查询在热缓存下运行，上述 0 不能推广成冷启动不读磁盘。最终目录大小 old=11054085、before=8025122、final=7680122 bytes，仅表示剩余文件大小。各轮资源快照同时保存匿名内存、文件页、rchar/wchar、read_bytes/write_bytes、CPU、OOM 事件和限额；没有用目录大小替代 I/O。

## 正确性、交付和剩余工作

最终 Docker 镜像通过：原公开 20/20、仓库额外 12/12、边界 13 组、scan/block/auto 共 1470 次独立 exact 校验、4 组批量强杀恢复、2 组字符串 WAL/checkpoint、13 项提交故障/CRC 检查。最终四版本三轮共 12000 条查询与独立 C++ 暴力真值核对 ID 和顺序，并用 Python math.fsum 重算返回距离；每轮重启逐行检查全部 10000 行和 float32 向量字节。额外候选规模的 1440 条查询也一致。

这是公开与本地回归通过，**不是正式 29 项通过**。平台 a3615e8 的六个具体输入及 stderr 仍不可得，不能声称一一对应根因已经确认。每天两次提测机会应由用户决定使用；本轮没有自动提交评测。原先缺失的真实 Linux/Docker 验证已经补上。

原有源码 2000 物理行目标仍未达成：当前 2269 行。ANN 仍 exact fallback；增量事务写集、SST 主读取/主恢复仍未完成。本轮没有扩大到全部故障矩阵或大规模冷态验收。

下一轮优先依据实际负载选择：自动批量写入主要是同步等待和向量文本转换；显式小事务才会突出整表复制。查询方面，宽范围过滤候选收集/映射已出现明确成本。只有恢复方案能保持同等持久性时，才考虑改变双文件同步设计。

复现工具：`docker_gate.py` 用实际镜像运行回归；`paired_compare.py` 调用既有 compare_run/独立 oracle，旋转顺序并强制检查验证字段；`prepare_selectivity.py` 改变候选规模；`profile_queries.py` 与 `build_diagnostic.py`/`profile_commits.py` 独立诊断。逐轮摘要和逐请求计时/计数存于 [results/server_20261115](../results/server_20261115)。完整原始数据库与结果仍保留在服务器隔离目录 `/mnt/SSD1/zzp/seekdb-round2-lite2000/iteration-20261115-ce21bb9`，证据压缩包已备份到 HDD2 的 results 目录。
