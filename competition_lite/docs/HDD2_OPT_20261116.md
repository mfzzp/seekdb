# HDD2 exact query optimization

The SQL tokenizer uses a string view for its fixed separator set. Keyword equality checks reject mismatched token lengths before uppercase conversion, including the long vector literal traversed by FROM lookup. Screen survivors are evaluated four at a time with the existing AVX-512 double kernel. Fewer than four survivors retain single-vector dispatch. Candidate ordering, the screening threshold, final double distances and primary-key tie breaking follow the existing path.

The final change preserves the baseline write implementation. Two copy-removal experiments passed correctness but showed worse HDD write timing, so both were reverted. The query-only third candidate still had a local E median below 0.5 amid write-time variation. The final candidate adds keyword length guards. All development rounds are retained in the evidence file. Three empty lines were removed to meet the 2000 physical runtime line limit.

All development and measurements ran under `/mnt/HDD2/zzp/oceanbase-competition/seekdb/.codex-lite2000-8afe25a`. The baseline is `8afe25ae9a40ab4c60df2fed2415f80bb49b1e00`. Its binary SHA256 was matched against the prior recorded Docker binary. The final candidate binary came from the fully checked Docker image.

## Three paired rounds

The frozen workload has 10000 rows, 128 dimensions, 100-row committed batches, and 1000 Exact K10 queries split evenly between unfiltered and category equality. Runs alternate baseline/candidate order, under the same 2 CPU and 2 GiB limits. Data files and results are on HDD2. Query wall time includes driver SQL generation and transport. Physical I/O comes from cgroup v2 io.stat, with memory.peak for container memory. Resource accounting follows the existing local harness, including shutdown writeback.

Paired local E values are 0.501834, 0.507724, 0.504034. Their median is **0.504034**, with baseline self-comparison 0.5. The official baseline and frozen evaluator are unavailable. These measurements establish a local result and carry HDD sync and scheduler variability.

## Validation

The final full Docker gate passed all recorded checks, including public and extra protocol cases, independent Exact oracles, matrix and kernel paths, screening, updates/rollback/restart, LSM model and corruption checks, commit faults and full-vector WAL recovery. Every performance run also passed independent Exact verification and 10000-row restart verification. The unchanged final query implementation additionally passed 384 screen-path oracle cases with VNNI packed screening disabled. All runtime sources total 2000 physical lines.

The full six verified performance reports, per-round T/B/M and E, binary/input hashes, and gate records are in [evidence.json](../results/hdd2_20261116/evidence.json). Raw server logs are retained under `optimization-20261116`. Development includes an initial compile failure from a mistyped hit-field name, corrected before the successful gates. No official platform evaluation was run.
