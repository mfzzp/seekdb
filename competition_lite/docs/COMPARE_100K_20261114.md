# 两组 10 万行新旧 C++ 对照：2026-11-14

写入优化有效，但查询表现分化。128 维无过滤 exact 加快，等值过滤退步；1024 维过滤查询退步更大。新版无过滤 ANN 召回率只有 **3.60%**，当前 ANN 路径不合格。不能宣称整体达到“比旧版快两倍”的目标。

- 每组每版 **1 次**，依次运行。21:29:02 开始，21:36:26 完成，共约 **7 分 24 秒**，包含独立真值计算和事后全量验证。运行期间未修改代码。

**运行与计时**

每次使用独立容器、独立 cgroup 和独立数据目录。CPU 配额为 2 核，数据库进程固定 CPU 0/1；内存 2 GiB，swap 和网络禁用。数据全部位于 SSD1 上 zzp 的新目录，映射到 `/data`。

为了在数据库关闭和同步完成后仍能采集 cgroup，容器保留一个空闲 sleep 进程，数据库通过 `docker exec -i` 执行。采样包含该轻量保留进程。该本地运行器不是官方驱动的逐字复刻。

写入主指标为第一批至最后一批响应完成的墙钟时间，包含读取预生成请求和响应处理；另保留逐请求计时和额外同步时间。查询均值是发送请求至解析完整响应的耗时；生成 SQL 在逐请求计时之外。建索引、18 个独立预热查询、关闭、重启、事后验证分别记录。

**正确性与 ANN**

- 两版在两组数据上的 exact 均通过独立真值的 ID、顺序和距离检查。独立 C++ 暴力程序直接读取原始 float32 文件，不调用数据库代码；每个返回向量的距离另用 Python `math.fsum` 核对。
- 四次运行均关闭、重启，再逐条核对全部 10 万行的所有普通字段和完整向量 float32 字节，全部通过。该过程在性能窗口之外。
- 新版冻结二进制通过官方公开协议用例 20/20。SQL 双单引号的 INSERT、UPDATE、DELETE、回滚、强杀日志重放和 checkpoint 重启验证通过；B256/B1024 宽批量恢复 4/4 通过。
- 1024 维 ANN：旧版本次召回为 1.0。新版非空查询整体平均为 **0.879230769**；其中无过滤 114 个查询平均召回仅 **0.035964912（3.60%）**，其余非空过滤组为 1.0。空集合不参与召回平均。
- 新版 ANN 的返回数量、ID 有效性、过滤、去重和距离核验通过，但召回率不合格。无过滤 ANN 的较低耗时不能算有效提速。

这些测试不替代完整隐藏功能准入和故障矩阵。

**下一轮应定位的问题**

1. 优先定位过滤 exact。128 维 category 已退步，1024 维 category、tenant、联合和范围过滤退步更大；主键小范围与 title 等值改善，需分别检查实际执行路径。
2. 检查无过滤 ANN 的训练样本覆盖、IVF 分区、候选选择与精排预算。当前测量不能直接证明哪一个环节造成 3.60% 召回，必须独立核验。
3. 1024 维查询窗口的辅助物理读入计数没有增加，CPU 时间由约 30 秒增至约 59 秒，接近对应墙钟时间。这提示先查 CPU 端的候选准备、过滤与距离计算开销；这是测量线索，不代替函数级剖析。
4. 此前审计的 LSM 主读路径、事务私有写集、文件发布和回收的崩溃安全等缺口仍然存在，本轮实验没有替代实现验收。
