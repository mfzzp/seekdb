# MiniVectorDB Lite

Standalone C++17 runtime for the competition JSONL contract. The root Dockerfile compiles `src/minivectordb_lite.cpp`, including `src/lsm_store.hpp`; it does not link the old root `minivectordb.cpp`.

The current engine uses authoritative SST reads/recovery, bounded ordered MemTables, spillable transaction/statement write sets, composite scalar index keys, streaming leveled compaction, checksummed manifest publication, WAL generation rotation and atomic vector GC. BEGIN no longer copies tables. Small tables retain bounded row/matrix caches and SIMD exact Top-K. Large tables stream from SST; no query-result cache is used.

Read the [architecture](docs/IMPLEMENTATION.md) and [LSM validation/measurements](docs/LSM_20261115.md). Earlier reports, including [ce497c6 measurements](docs/SERVER_ITERATION_20261115.md), describe their dated implementations. `a3615e8` failed the platform correctness gate. Local/public tests do not guarantee the hidden gate. Official submissions remain user-controlled, limited to two per day; pushing does not submit a run.

Ordinary nonempty commits synchronize a complete physical WAL transaction, including raw float32 vector bytes. Automatic SST/Manifest publication and checkpoint synchronize the referenced vector boundary before retiring recovery dependencies. Recovery restores vectors at fixed offsets before applying committed keys; I/O failure freezes the engine until restart. Manifest v4 prevents older binaries from silently using the new durability contract; v3 is upgraded through recovery and checkpoint. Legacy Lite STATE/token-WAL import remains supported; v2/JSON STATE requires an empty legacy WAL.

`LITE_COMMIT_MODE=wal|dual` selects full-vector WAL (default) or the previous two-file-sync contract for controlled comparison. Already-synced full WAL pages are released from page cache by a best-effort hint; `LITE_WAL_CACHE=1` retains them for comparison. `LITE_WAL_BATCH=1` experiments with bounded combined WAL writes and remains off by default because the first three-round comparison found no stable time benefit. These settings do not change client transaction batch sizes or relax acknowledged-commit durability.

`LITE_EXACT_PATH=auto|scan|block` defaults to scan. Hot tables can compare Block pruning; cold tables use exact streaming scans with the same filtering, widened distance arithmetic and ties. ANN explicitly falls back to exact. Query diagnostics use `LITE_PROFILE=1`; separate write diagnostic binaries are generated by `bench/build_diagnostic.py`. Final timing does not use instrumentation.

Exact defaults to a batch matrix scan for unfiltered cached data, reusing the widened query for 128-dimensional AVX-512 distances, and interleaving two vectors for filtered candidates. Row IDs are fetched only when a distance can enter Top-K; ties still use the real primary key. Per-ISA double accumulation order is retained. `LITE_L2_BATCH=auto|1|2|4`, `LITE_LATE_ID=0`, `LITE_MATRIX_SCAN=0`, `LITE_QUERY_WIDE=0`, and `LITE_SIMD=auto|avx2|scalar` support isolated comparisons. `LITE_EARLY=1` enables the measured-but-default-off partial distance experiment. `LITE_MATRIX_MB=0` now genuinely disables the matrix; mmap batches never retain a pointer across a window remap.

From a clean Git source tree:

```sh
python3 competition_lite/tools/check_lines.py
python3 competition_lite/bench/docker_gate.py \
  --source . --root /mnt/SSD1/zzp/lite-gate-new --image lite:verified
python3 competition_lite/bench/lsm_capacity_check.py \
  --image lite:verified --root /mnt/SSD1/zzp/lite-capacity-new
```

The line checker includes every runtime `.cpp`, `.hpp`, and `.h`, comments and blank lines, against the original 2000-line limit. Tests are outside that count. The Docker gate includes public/extra cases, exact oracles, syscall faults, LSM model/corruption checks, publication failures and repeated crashes during large-transaction recovery. Capacity testing uses a 128 MiB no-swap container with a host-side driver.

Defaults: 4 MiB MemTable/write-set budget, 8 MiB target SST, 32 MiB row-cache estimate, 64 MiB matrix, 32 MiB mmap window. `LITE_ROW_CACHE_MB=0` forces disk reads. Compaction is synchronous. This is a single-writer engine without concurrent-client MVCC; oversized cold-query result materialization fails explicitly rather than silently truncating rows.
