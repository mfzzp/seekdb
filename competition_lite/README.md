# MiniVectorDB Lite

Standalone C++17 runtime for the competition JSONL contract. The root Dockerfile compiles `src/minivectordb_lite.cpp`, including `src/lsm_store.hpp`; it does not link the old root `minivectordb.cpp`.

The current engine uses authoritative SST reads/recovery, bounded ordered MemTables, spillable transaction/statement write sets, composite scalar index keys, streaming leveled compaction, checksummed manifest publication, WAL generation rotation and atomic vector GC. BEGIN no longer copies tables. Small tables retain bounded row/matrix caches and SIMD exact Top-K. Large tables use a bounded compact query view or ordered SST reads; no query-result cache is used.

Read the [architecture](docs/IMPLEMENTATION.md), [large-table read-path measurements](docs/READPATH_20261115.md) and [initial LSM validation](docs/LSM_20261115.md). Earlier reports, including [ce497c6 measurements](docs/SERVER_ITERATION_20261115.md), describe their dated implementations. `a3615e8` failed the platform correctness gate. Local/public tests do not guarantee the hidden gate. Official submissions remain user-controlled, limited to two per day; pushing does not submit a run.

Ordinary nonempty commits synchronize a complete physical WAL transaction, including raw float32 vector bytes. Automatic SST/Manifest publication and checkpoint synchronize the referenced vector boundary before retiring recovery dependencies. Recovery restores vectors at fixed offsets before applying committed keys; I/O failure freezes the engine until restart. Manifest v4 prevents older binaries from silently using the new durability contract; v3 is upgraded through recovery and checkpoint. Legacy Lite STATE/token-WAL import remains supported; v2/JSON STATE requires an empty legacy WAL.

`LITE_COMMIT_MODE=wal|dual` selects full-vector WAL (default) or the previous two-file-sync contract for controlled comparison. Already-synced full WAL pages are released from page cache by a best-effort hint; `LITE_WAL_CACHE=1` retains them for comparison. `LITE_WAL_BATCH=1` experiments with bounded combined WAL writes and remains off by default because the first three-round comparison found no stable time benefit. These settings do not change client transaction batch sizes or relax acknowledged-commit durability.

`LITE_EXACT_PATH=auto|scan|block` defaults to scan. Hot tables can compare Block pruning; cold tables use exact streaming scans with the same filtering, widened distance arithmetic and ties. ANN explicitly falls back to exact. Query diagnostics use `LITE_PROFILE=1`; separate write diagnostic binaries are generated by `bench/build_diagnostic.py`. Final timing does not use instrumentation.

Exact defaults to a batch matrix scan for unfiltered cached data, reusing the widened query for 128-dimensional AVX-512 distances, and interleaving two vectors for filtered candidates. Row IDs are fetched only when a distance can enter Top-K; ties still use the real primary key. Per-ISA double accumulation order is retained. `LITE_L2_BATCH=auto|1|2|4`, `LITE_LATE_ID=0`, `LITE_MATRIX_SCAN=0`, `LITE_QUERY_WIDE=0`, and `LITE_SIMD=auto|avx2|scalar` support isolated comparisons. `LITE_EARLY=1` enables the measured-but-default-off partial distance experiment. `LITE_MATRIX_MB=0` now genuinely disables the matrix; mmap batches never retain a pointer across a window remap.

Hot single-equality Top-K queries can reuse sorted vector slots. `LITE_HOT_POSTINGS_KB` defaults to 1024 across one table/column; zero disables retention. The estimate includes keys, map nodes and vector capacity. Mutations, rollback, failed statements, GC, table/column changes and slot rebuilds invalidate it. No query answers or extra vectors are cached; unsupported predicates and budget rejection use the prior path. See [small-table comparison](docs/SMALL_HOT_20261116.md).

Vector literals use a checked double `from_chars` conversion before the existing float32 conversion. Leading plus and conversion errors retain the `strtod` fallback; dimensions, characters and finite-value checks remain. `LITE_FAST_PARSE=0` restores the prior conversion for comparisons. See [default-workload write and query results](docs/SMALL_PARSE_20261116.md).

Responses append JSON into one reserved output buffer with 17-digit double conversion; hot query results move their arrays into the response. `LITE_JSON_FAST=0` restores the legacy encoder for comparisons. Random bitwise round trips, types, escaping and the actual Docker protocol/recovery gate pass. The single-round default workload query interval improves 5.36% against a freshly rerun de0eed2; see [query output measurements](docs/QUERY_OUTPUT_20261116.md).

Eligible 128D hot matrices retain bounded int8 screening codes. AVX-512BW computes integer candidate distances; AVX-512 VNNI optionally scans 16 interleaved vectors with four accumulators. A conservative triangle/error bound rejects candidates, while final ranking and distances use the original double kernel. `LITE_DISTANCE_SCREEN=0` disables the cache/path; `LITE_SCREEN_DOT=0` keeps only row codes. Unsupported CPUs/dimensions, cold reads, absent matrices and nondefault floating-point environments fall back. Codes share matrix invalidation and budget checks. Default extra cache is 2.6 MB and is built during initial query preparation. One-round results versus 05212db: unfiltered requests 1.88x, mixed requests 1.50x, query interval 1.40x; mixed end-to-end 2x was not reached. See [measurements](docs/DISTANCE_SCREEN_20261116.md) and [bound analysis](docs/DISTANCE_SCREEN_BOUND.md).

Filtered candidates that occupy a contiguous physical matrix interval can reuse the same batch scan at that interval's offset. This never expands the filtered candidate set. `LITE_CONTIGUOUS_SCAN=0` disables the experiment; `contiguous_candidates` and `matrix_scan_vectors` expose actual use in diagnostic runs.

Contiguous physical vectors now borrow mmap pages instead of duplicating the float32 matrix. Each query reacquires the mapping; mutations invalidate descriptors, and fragmented layouts retain the owned-copy fallback. `LITE_MATRIX_VIEW=0` restores copying. Three rounds with physical device I/O show a 16.2% container-peak reduction versus 830fbba; timing differences vary between runs. See [composite measurements](docs/COMPOSITE_VIEW_20261116.md). `bench/score_compare.py` computes a clearly labeled local-reference E and rejects missing physical I/O.

The line checker includes every runtime `.cpp`, `.hpp`, and `.h`, comments and blank lines, against the original 2000-line limit. Tests are outside that count. The Docker gate includes public/extra cases, exact oracles, syscall faults, LSM model/corruption checks, publication failures and repeated crashes during large-transaction recovery. Capacity testing uses a 128 MiB no-swap container with a host-side driver.

Defaults: 4 MiB MemTable/write-set budget, 8 MiB target SST, 32 MiB row-cache estimate, 64 MiB matrix, 32 MiB mmap window. `LITE_ROW_CACHE_MB=0` disables the full-row hot path. Compaction is synchronous. This is a single-writer engine without concurrent-client MVCC; oversized cold-query result materialization fails explicitly rather than silently truncating rows.

The LSM read cache separates immutable `TableReader` objects from cursor positions. Readers retain verified indexes and file references; decoded blocks are reused by file identity and block number. `LITE_READ_CACHE_MB` defaults to 16 MiB; zero disables retention. The budget includes estimated reader, descriptor, index, decoded-record and container overhead, with at most 64 retained readers. Active cursor pins and temporary decode buffers are additional working memory, reported separately and covered by container peak measurements. Cache misses still verify CRC; `--check` bypasses cached data to verify the files. Retired files survive until their last active reader releases them.

Filtered cold reads collect at most 1024 keys per batch and merge ordered cursors across SSTs, MemTables and private write sets. `LITE_LSM_READ=auto|batch|scan` selects adaptive per-SST traversal, forced batch lookup or primary-row scan with filtering. Explicit `batch` and `scan` also bypass the compact view, so they are useful storage-path controls.

`LITE_QUERY_VIEW_MB` defaults to 8 MiB across tables; zero disables compact views. A view keeps 16-byte primary-key/vector-offset descriptors and, when the same budget permits, positions from a persisted scalar index. Exact validates supported predicates before Top-K and fetches remaining output fields only for winners. Unsupported predicates or an oversized view use ordered SST reads. Mutation, rollback and vector GC invalidate views. Full rows and raw vectors are not copied into this view.

`LITE_MMAP_KEEP_MB` defaults to 1024 MiB of retained virtual mappings; zero restores a single active window. Mappings reuse the existing vector file and do not lock physical pages. Resident file pages still count toward container memory. One active window is required even when the retention budget is smaller; mappings are cleared before truncation or vector-file replacement. Diagnostic queries report reader/index/block work, unique blocks, decoded records, retained/live cache estimates, descriptor bytes and mapping creations. Run diagnostics separately from final timing.

Geometric radius-sorted blocks are retained as a reproducible **bench-only experiment**, generated outside `src/` by `bench/geo_experiment.py`. They do not alter the production Docker build or enable a `geo` mode in the submitted executable. See [measured decision](docs/GEOMETRY_EXPERIMENT_20261115.md); no tested complete workflow beat scan after including construction.
