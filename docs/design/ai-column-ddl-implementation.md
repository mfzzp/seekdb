## Parser and validation

The existing four-child ordinary column-definition node is retained. Its attributes
may contain `T_AI_COLUMN`, which carries the model call, options, and separate raw
prompt/prefix text captured by Bison locations. This avoids re-lexing SQL text to
find commas inside strings or function calls. No warnings are disabled; unused
`opt_equal_mark` values are consumed explicitly. CREATE and ALTER ADD/MODIFY share
the column-definition resolver. `SHOW AI COLUMNS FROM [database.]table` resolves to
a native SELECT over the persisted catalog with a reference to the user table for
native privilege checking.

Only AI_COMPLETE and AI_EMBED roots with a literal model name are accepted. The
model is looked up through ObSchemaGetterGuard and its category is checked without
resolving an HTTP endpoint or evaluating the model expression. Supported prompt
syntax is deliberately restricted to column references, scalar literals and the
deterministic concat/lower/upper/coalesce/ifnull/replace/trim/substring functions.
The prompt is also bound/type-checked through the existing generated-expression
builder; the model call itself never goes through that builder.

Options accept async mode only and nonnegative max_retries up to INT32_MAX, with a
default of 2. Unknown or duplicate options are rejected. Embedding results require
a vector type and matching explicit dimension. Completion results accept string,
JSON and supported scalar numeric/datetime types. Defaults, non-null constraints,
autoincrement and generated-column definitions are not accepted for AI results.

CREATE dependency binding occurs after all user-column definitions have been
resolved, so forward references are supported. Dependencies are stored as resolved
column IDs. AI-to-AI, self, hidden and generated-column dependencies are rejected.
The current ALTER binder uses the existing table schema; references to columns
newly added in the same multi-action ALTER are not supported. Renaming or changing
the SQL type of an existing dependency is rejected instead of leaving stale SQL.

JSON and numeric definitions retain explicit type instructions. Both the original
prompt and the type instruction are serialized separately, alongside an enriched
normalized expression. The future Worker must use these separate fields to build
provider-specific system instructions without changing the original user input.
No HTTP result validation or request execution is claimed in this DDL stage.

## Schema and transaction paths

AiColumnDefinition is implemented in the existing ob_column_schema.h/.cpp pair.
It records expression, original prompt, type instruction, model identity/category,
dependency names/IDs, retry budget, expected result type/vector dimension and hidden
column IDs. ObColumnSchemaV2 owns a serialized definition blob rather than storing
it in default values or enum/vector extended type info.

The blob participates in reset, assign, conversion sizing, serialization,
deserialization, SQL writing to __all_column/history, and schema loading from those
tables. ALTER's explicit attribute-copy path copies the blob as well. Ordinary
MODIFY retains the definition; changing its result SQL type requires a new AI
declaration. Replacing an existing AI declaration retains its hidden column IDs.

CREATE allocates state/request/result-spec hidden columns through the native table
schema. ALTER ADD appends hidden ADD actions immediately after its AI result; the
root DDL service updates the definition after assigning actual column IDs. When
MODIFY converts an ordinary column, hidden actions precede that modification and
the root DDL service binds their actual IDs by their generated names. Dropping an
AI result adds native DROP actions for its hidden columns. Dropping a referenced
ordinary dependency is rejected.

The __all_ai_column catalog and history (IDs 1131/1132, unused in the base source)
are generated by the existing inner-table generator. Current definitions and
history records are written through the caller's ObISQLClient in the existing DDL
transaction. The implementation does not create a second connection or transaction.
The same transaction writes ordinary column metadata, hidden columns, the AI blob,
catalog mirror and schema-operation records; failures propagate to the caller.
Physical table/column deletion also removes current catalog rows and writes history.

The three hidden cells are only schema in this phase. DML invalidation, request
tokens, PENDING/READY/FAILED transitions, durable task registration and grouped
publication remain stages 2 and 3. Business assignment protection and Strict Read
are not implemented by this patch.

## Build membership

No C++ source file is added. Modified C++ files already belong to the production
Share, Observer, Rootserver and SQL inventories. The new public structure is in an
existing owned header. Its serialization definitions live in ob_column_schema.cpp.

Inner-table generated source/header files are build outputs. Top-level CMake hashes
the definition source and reruns generation when it changes. New system tables and
their generated LOB auxiliaries land in the already-listed 1101_1150, 51101_51150
and 61101_61150 source ranges. Regenerate and compile on Linux; no generated output
has been fabricated or checked into this worktree.

## Ubuntu 24.04 validation

Use the official compiler/dependency setup and this exact worktree content. Build:

```bash
set -o pipefail
python3 unittest/share/inner_table/test_ai_column_catalog.py
./build.sh release --init --make -j"$(nproc)" 2>&1 | tee ai-column-build.log
```

Use a fresh, isolated instance for bootstrap verification. Set OBCLIENT and
MYSQLTEST to the installed runtime executables; these commands use the same admin
test account and init SQL as the repository runner:

```bash
export OBCLIENT=/absolute/path/to/obclient
export MYSQLTEST=/absolute/path/to/mysqltest
export AI_DDL_INSTANCE="$(mktemp -d /tmp/seekdb-ai-ddl.XXXXXX)"
export AI_DDL_PORT=2887
python3 .github/script/seekdb/sdb.py start \
  --binary "$PWD/build_release/src/observer/seekdb" \
  --base-dir "$AI_DDL_INSTANCE" --port "$AI_DDL_PORT"
python3 .github/script/seekdb/sdb.py wait-ready --client "$OBCLIENT" \
  --base-dir "$AI_DDL_INSTANCE" --host 127.0.0.1 --port "$AI_DDL_PORT" \
  --user root --timeout 600
"$OBCLIENT" -h127.0.0.1 -P"$AI_DDL_PORT" -uroot -A -c -Doceanbase < tools/deploy/init.sql
"$OBCLIENT" -h127.0.0.1 -P"$AI_DDL_PORT" -uroot -A -c -Dtest < tools/deploy/init_user.sql
mkdir -p "$AI_DDL_INSTANCE/test-tmp" "$AI_DDL_INSTANCE/test-logs"
cd tools/deploy
for test_name in ai_column_ddl ai_column_ddl_extended; do
  "$MYSQLTEST" --host=127.0.0.1 --port="$AI_DDL_PORT" \
    --user=admin --password=admin --database=test --silent \
    --tmpdir="$AI_DDL_INSTANCE/test-tmp" --logdir="$AI_DDL_INSTANCE/test-logs" \
    --test-file="mysql_test/test_suite/ai_column/t/$test_name.test" \
    --result-file="mysql_test/test_suite/ai_column/r/mysql/$test_name.result"
done
```

Also verify a full stop/start with an AI table left in place, followed by ordinary
MODIFY and SHOW. Check both the catalog and nonempty __all_column.ai_column_info
after that MODIFY: catalog rows alone cannot prove schema-blob reload worked.
From the repository root, with the same runtime variables:

```bash
"$OBCLIENT" -h127.0.0.1 -P"$AI_DDL_PORT" -uadmin -padmin -Dtest <<'SQL'
CREATE DATABASE ai_column_reload_check;
CALL DBMS_AI_SERVICE.CREATE_AI_MODEL('ddl_reload_completion',
  '{"type":"completion","model_name":"ddl-reload-model"}');
CREATE TABLE ai_column_reload_check.docs(
  id BIGINT PRIMARY KEY, content VARCHAR(100),
  result JSON AI COLUMN (AI_COMPLETE('ddl_reload_completion', content))
    WITH (max_retries=7)
);
SQL
python3 .github/script/seekdb/sdb.py stop --base-dir "$AI_DDL_INSTANCE"
python3 .github/script/seekdb/sdb.py start \
  --binary "$PWD/build_release/src/observer/seekdb" \
  --base-dir "$AI_DDL_INSTANCE" --port "$AI_DDL_PORT"
python3 .github/script/seekdb/sdb.py wait-ready --client "$OBCLIENT" \
  --base-dir "$AI_DDL_INSTANCE" --port "$AI_DDL_PORT" --user root --timeout 600
"$OBCLIENT" -h127.0.0.1 -P"$AI_DDL_PORT" -uadmin -padmin -Dtest <<'SQL'
ALTER TABLE ai_column_reload_check.docs MODIFY COLUMN result JSON;
SHOW AI COLUMNS FROM ai_column_reload_check.docs;
SELECT COUNT(*)=1 AND MIN(LENGTH(c.ai_column_info))>0 AND MIN(a.max_retries)=7 AS reload_ok
FROM oceanbase.__all_ai_column a
JOIN oceanbase.__all_column c ON c.table_id=a.table_id AND c.column_id=a.column_id
JOIN oceanbase.__all_table t ON t.table_id=a.table_id
JOIN oceanbase.__all_database d ON d.database_id=t.database_id
WHERE d.database_name='ai_column_reload_check' AND t.table_name='docs';
DROP TABLE ai_column_reload_check.docs;
CALL DBMS_AI_SERVICE.DROP_AI_MODEL('ddl_reload_completion');
DROP DATABASE ai_column_reload_check;
SQL
```
